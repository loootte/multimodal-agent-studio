# ADR 0001：先提交蓝图，不提交实现

## 状态

已接受。

## 背景

这个工程要同时满足三件事：多模态模型、可用的界面、能按业界做法扩展的 Agent 运行时。如果第一天就生成脚手架代码，目录和依赖会在契约写清之前定死。

## 决定

仓库的第一版只包含章程、架构、模型契约、界面范围、目录约定和路线图。不包含应用源码、依赖清单和可运行服务。

第 1 阶段才选择语言和框架，并写成下一条架构决定。

## 后果

- 产品本身现在还不能跑起来。这是有意的。
- 评审看的是边界和顺序，不是样例代码。
- 一旦开始写产品代码，新增的顶层目录要和 `docs/repository-layout.md` 一致，或者先改那份文档。

## 补充

issue #1 增加了 `poc/comfyui`。这是蓝图之外的本地验证脚本，用来向本机 ComfyUI 提交固定工作流。它不选择产品语言，也不占用 `apps/` 或 `services/`。上面的阶段顺序不变。
