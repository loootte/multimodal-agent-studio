# ADR 0003：本地数据隔离

## 状态

已接受。

## 背景

第三方模型跑在本机进程外面。画面描述、留下的文字、上传的文件，以及会话消息里抄到的这些内容，都是本地数据。[issue #11](https://github.com/loootte/multimodal-agent-studio/issues/11) 把画面描述留在本机，模型只拿到工具契约和句柄。[issue #12](https://github.com/loootte/multimodal-agent-studio/issues/12) 用专用工具接受、列出和删除文字或文件。

这条决定记下这个原则。以后新增的工具或适配器继续遵守，不把正文交回供应商、别的会话或其他外部系统。

## 决定

本地数据留在本机。第三方模型只能使用工具契约，不能读取本地数据。本地数据由专用工具管理。本机进程以外的访问先有授权，没有授权就拒绝。

本地数据包括：内容正文、上传文件的字节、原始文件名、本机路径，以及消息和事件里抄到的这些内容。生成文件仍要会话和 `artifact_id` 同时正确才能读取。供应商密钥继续按 [ADR 0002](0002-implementation-stack.md)，不进源码、日志和接口响应。

- **只给工具契约。** 第三方模型看到的是工具名字、说明和参数模式，以及句柄、种类、大小、用途、状态这些公开字段。参数里没有正文、字节、路径或原始文件名。模型自己写的画面描述丢掉，不作为本地正文。
- **不读取本地数据。** 供应商请求、工具回传和之后的轮次都不带已入库的正文或文件字节。历史里出现过的正文换成不含正文的句柄说明。`services/gateway` 是唯一出口，打开连接之前检查载荷。正文出现在工具契约以外就失败，连接不打开。工具契约里的说明文字不参与这道检查。
- **专用工具管理。** 接受、列出、删除和按句柄使用，都走已注册的工具。运行时校验参数并执行。模型在文本里说已经执行，不算执行。现在这组工具是 `accept_local_content`、`list_local_content`、`forget_local_content` 和 `generate_image`。不为此新建 MCP 服务器、数据库、`services/tools` 或 `packages/artifacts`。
- **外部访问要授权。** 外部包括第三方模型、其他会话、ComfyUI，以及以后任何本机进程以外的调用方。一次授权只覆盖该工具写明的动作：文字句柄允许本机把用户提交的文字注入 `generate_image`；文件句柄不允许把字节交给 ComfyUI；删除只作用于本会话，并清掉本会话消息里的正文副本。其他会话看到这枚句柄，如同它不存在。进程只听 `127.0.0.1`。现在没有登录，也没有远程授权，缺省拒绝。

## 后果

- 现行路径写在 [docs/architecture.md](../architecture.md)，出口检查写在 [docs/model-gateway.md](../model-gateway.md)。离线检查在 `apps/web/check.py`。
- 新工具若要读或写本地数据，参数收句柄，结果只回公开字段，并继续接受网关的同一道出口检查。
- 本决定不实现登录、跨用户授权或远程 API。要做那些能力时，先写明谁授权、授权看哪一笔数据，再另写架构决定。
- issue #11、issue #12 和本决定都不把路线图任一阶段标成完成。
