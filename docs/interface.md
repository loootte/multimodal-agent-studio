# 界面

首版是 Web 应用。它要让人完成多模态任务，并看见 Agent 做了什么。

## 谁在用

一个已登录用户，在自己的会话里工作。第 3 阶段可以先用单用户开发登录，第 6 阶段再换成真正的账号。界面结构从第 3 阶段起就按「会话属于某个用户」来摆，避免以后推倒。

## 首版画面

三个区域：

1. 会话列表：标题、更新时间、是否仍在运行。
2. 对话：用户消息、附件预览、助手回答、工具时间线。
3. 输入区：文本框、附件按钮、发送、停止。

附件按钮接受图片、音频、视频和普通文件。界面按媒体类型显示预览或文件名。不支持的类型在选择时就说明，不等模型失败。

助手回答以流式文本出现。工具时间线贴在这一轮回答上，每一条有工具名、状态（等待确认、运行、成功、失败）和简短结果。参数里的密钥和过长正文不展开。

顶部显示当前模型，以及这个模型接受的输入模态。用户换模型时，如果已添加的附件不被接受，发送按钮不可用，并写明原因。

## 必须能走完的路径

- 只发文字，看到流式回答。
- 带一张图片提问，图片在对话里可回看。
- 运行中按下停止，界面不再追加新的增量。
- 模型请求一个需要确认的工具时，界面给出确认和拒绝。拒绝后运行继续，并把拒绝作为工具结果。
- 网关返回 `modality_unsupported` 或 `payload_too_large` 时，用这句话对应的人话提示，而不是堆栈。

## 不做

- 可视化编排画布
- 插件商店
- 主题定制系统
- 协作光标和多人同时编辑同一会话
- 把追踪系统的原始日志直接铺在主界面。开发时可以有一个折叠的调试抽屉，默认关闭

## 实现时的约束

这些约束留给第 3 阶段。issue #9 落地了文字聊天里的这些：刷新后能看见已完成的消息，停止后不再追加增量，页面断开后接回同一次运行而不是再请求一次，颜色用一套小刻度，发送和停止能用键盘完成。issue #10 在同一条助手消息上显示文生图的工具调用、进度和图片。issue #12 在模型调用 `accept_local_content` 之后，用对话框收文字或文件。文件字节留在本机会话目录，不随聊天消息发给模型。图生图、出视频、登录、工具确认、重新生成、改比例和用作参考仍不在这一刀。

- 界面状态以服务端的运行为准。刷新后能恢复已完成的步骤。
- 流式通道断开后可以重连到同一运行，而不是再跑一遍。
- 颜色和字号使用一套小的设计刻度。首版优先可读，不先做视觉主题。
- 主要路径能用键盘完成：焦点在输入框、发送、停止、确认工具。
