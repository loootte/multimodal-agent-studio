# 模型网关契约

网关对上只提供一种请求。供应商适配器负责翻译。

## 模型能力

每个模型标识必须声明：

| 字段 | 含义 |
| --- | --- |
| 输入模态 | `text`、`image`、`audio`、`video` 的子集 |
| 输出模态 | 首版只承诺 `text`。图像或音频生成不在前六个阶段 |
| 流式 | 文本增量是否可用 |
| 工具调用 | 是否支持结构化工具调用 |
| 上下文上限 | 可放入的输入上限，按供应商单位记录，并注明单位 |
| 限制 | 单文件大小、时长、张数 |

运行时在调用前读这份声明。声明里没有的模态，适配器必须拒绝。

## 统一请求

一条请求包含：

- 模型标识
- 系统指令
- 消息列表。每条消息有角色，以及一串部件
- 可选的工具模式
- 生成参数：温度、最大输出、停止条件。适配器不认识的参数要显式忽略并记在追踪里，不能假装生效

部件类型：

| 类型 | 内容 |
| --- | --- |
| `text` | 纯文本 |
| `image` | 工件标识，外加媒体类型 |
| `audio` | 工件标识，外加媒体类型和时长 |
| `video` | 工件标识，外加媒体类型和时长 |
| `file` | 工件标识。能否阅读取决于模型和预处理，不把所有文件都假装成文本 |

网关不接收裸文件字节作为长期接口。上传走工件库，请求里只放标识。测试夹具可以在适配器内加载本地文件，那不属于对外契约。

## 统一事件

流式输出使用这些事件，顺序保持：

1. `run.started`
2. 零个或多个 `message.delta`
3. 零个或多个 `tool.requested`
4. `message.completed` 或 `run.failed`

失败事件带稳定代码，至少区分：

- `modality_unsupported`
- `payload_too_large`
- `rate_limited`
- `timeout`
- `cancelled`
- `provider_error`
- `invalid_tool_call`

## 适配器规则

- 一个适配器对应一个供应商。
- 密钥从环境读取，构造函数不接收写死的密钥。
- 把供应商的工具调用归一成名字加 JSON 对象。解析失败用 `invalid_tool_call`，不要把原始文本当成已执行的工具。
- 超时由网关执行，不依赖供应商客户端的默认值。

## 首批模态承诺

| 模态 | 第 1 阶段 | 说明 |
| --- | --- | --- |
| 文本进、文本出 | 要实现 | 含流式 |
| 图像进、文本出 | 要实现 | 常见问答和描述 |
| 音频进、文本出 | 契约先固定 | 可以返回 `modality_unsupported` |
| 视频进、文本出 | 契约先固定 | 同上 |
| 任意模态生成媒体 | 不做 | 见路线图「明确延后」之外的范围控制：生成图片、语音不在网关首版 |

预处理（抽帧、转写、压缩）如果以后需要，放在网关之前的独立步骤，并在运行轨迹里记一笔。不要藏在适配器里让同一次请求的输入和模型实际看到的内容对不上。
